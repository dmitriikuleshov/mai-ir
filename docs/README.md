# Документация проекта MAI-IR

Эта папка содержит материалы для последовательной сдачи выполненных лабораторных
работ. Документы описывают фактическую реализацию в ветке `lesson-04_1`: команды,
структуры данных, алгоритмы, результаты, тесты, ограничения и порядок демонстрации.

## В каком порядке читать

1. [Общая схема системы](00-system-overview.md) — окружение, поток данных,
   каталоги и коллекции MongoDB.
2. [Добыча и анализ корпуса](01-corpus-analysis.md) — три источника и ноутбуки.
3. [Поисковый робот](02-web-crawler.md) — массовая загрузка и обновление документов.
4. [Токенизация](03-tokenization.md) — извлечение текста и правила токенов.
5. [Лемматизация](04-lemmatization.md) — нормализация словоформ и частоты.
6. [Закон Ципфа–Мандельброта](05-zipf-law.md) — статистика корпуса и график.
7. [Булев индекс](07-boolean-index.md) — построение дискового инвертированного индекса.
8. [Булев поиск](08-boolean-search.md) — язык запросов и обработка posting lists.
9. [Сценарий общей демонстрации](09-demonstration.md) — что запускать и показывать
   преподавателю по шагам.
10. [Демонстрация MongoDB](10-mongodb-demonstration.md) — как показать коллекции,
    документы, индексы и состояние обхода через `mongosh` и MongoDB Compass.
11. [Быстрый показ за 10 минут](11-quick-10-minute-demo.md) — компактная
    последовательность команд и реплик для демонстрации всех выполненных работ.

Нумерация 01–08 соответствует пунктам оценивания в
[README курса](https://github.com/toshunster/MAI-IR/blob/main/README.md). Пункт 06
«Оценка качества поиска» в текущей ветке не реализован, поэтому отдельного документа
для него нет.

## Текущее состояние

Реализованы:

- анализ трёх источников на выборках по 30 документов;
- асинхронный crawler с MongoDB, повторным обходом и защитой от дублей;
- потоковое выделение текста из HTML;
- токенизация и лемматизация на C++;
- подсчёт частот, статистики и закона Ципфа–Мандельброта;
- собственный дисковый булев индекс на C++ без STL-контейнеров;
- консольный булев поиск через стандартные потоки.

Остаются два формальных ограничения относительно максимального варианта требований
курса:

- текущий корпус содержит 170 393 сырых и 151 182 принятых документа, а для оценки
  5 в общем README преподавателя указано больше 1 миллиона документов;
- для интерфейсной поисковой части пока есть консольная утилита, но ещё нет
  обязательного HTML-веб-интерфейса.

Архитектура crawler, лингвистики и индексатора не требует помещения всего корпуса
в оперативную память, поэтому её можно применять после увеличения корпуса.

## Как изучать документы, а не просто читать

Для каждой лабораторной использовать одинаковый цикл:

1. Прочитать теорию и выписать определения незнакомых слов.
2. Самостоятельно воспроизвести ручной пример: HTML extraction, token trace,
   frequency delta, Zipf ranks, mini-index или Boolean intersection.
3. Открыть указанные функции в `src` и сопоставить каждый шаг примера со строками
   кода.
4. Выполнить команды проверки и посмотреть реальные MongoDB/файловые данные.
5. Закрыть документ и ответить на контрольные вопросы своими словами.
6. Открыть `09-demonstration.md` и проговорить соответствующий этап как на защите.

Если ручной пример невозможно объяснить без подсматривания, к следующей работе
переходить рано: downstream-компоненты опираются на понимание предыдущих.

- реальные структуры данных;

- пошаговая трассировка одного примера;
- алгоритмы и оценки сложности;
- инварианты корректности;
- обновления и сценарии сбоя;
- команды диагностики;
- количественные результаты;
- альтернативные решения и причины выбора;
- ограничения;
- контрольные вопросы с развёрнутыми ответами;
- конкретный порядок демонстрации преподавателю.
