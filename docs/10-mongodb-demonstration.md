# Как показать MongoDB преподавателю

Этот документ нужен именно для защиты проекта. Он объясняет:

- зачем в проекте используется MongoDB;
- какие коллекции созданы и кто их заполняет;
- как показать базу через MongoDB Compass;
- как показать те же данные без Compass через `mongosh`;
- какие команды вводить и какой результат ожидать;
- что говорить преподавателю на каждом шаге.

Для основной демонстрации удобнее MongoDB Compass: в нём структура документов и
индексы видны визуально. `mongosh` нужно подготовить как обязательный запасной
вариант: он работает даже без графического интерфейса и позволяет выполнить
точные воспроизводимые запросы.

Короткий ответ: устанавливать Compass для работы программ не обязательно.
MongoDB работает в Docker, а Compass и `mongosh` являются только двумя клиентами
для просмотра одной и той же базы.

## Как пользоваться этой инструкцией

- Если Compass уже установлен — выполнить подготовку из раздела 3, затем идти в
  раздел 5.
- Если Compass не нужен — выполнить подготовку из раздела 3 и идти в раздел 6.
- Перед защитой выучить объяснения из раздела 7.
- Если преподаватель даёт мало времени — использовать порядок из раздела 8.
- Если подключение не работает — открыть раздел 9.

## 1. Что нужно понимать перед показом

### MongoDB в этом проекте

MongoDB — постоянное хранилище промежуточных данных поисковой системы:

```text
Интернет
   │
   ▼
crawler на Python
   │
   ▼
MongoDB: сырой HTML и состояние обхода
   │
   ▼
linguistics на C++
   │
   ▼
MongoDB: извлечённый текст, токены, леммы и частоты
   │
   ▼
boolean_index на C++
   │
   ▼
results/boolean_index/*.bin
```

Сам булев индекс хранится не в MongoDB. Он записывается в собственные бинарные
файлы в `results/boolean_index/`. MongoDB хранит документы и результаты их
предварительной обработки, из которых этот индекс строится.

### Термины, которые могут встретиться на защите

| Термин | Простое объяснение |
|---|---|
| база данных | в проекте это база `mai_ir` |
| коллекция | аналог таблицы, например `documents` |
| документ MongoDB | одна BSON-запись с полями одного документа корпуса |
| `_id` | уникальный идентификатор записи MongoDB |
| query/filter | условие выбора документов |
| projection | перечень полей, которые нужно показать или скрыть |
| index | структура MongoDB для ускорения запросов и контроля уникальности |
| unique index | индекс, который запрещает дублирующиеся значения |
| aggregation | последовательность операций группировки и подсчёта |
| upsert | обновить существующую запись или создать новую, если её ещё нет |

### Что означает «делать лабораторную вручную»

Не нужно вручную добавлять сотни тысяч документов через Compass. Программы сами
формируют данные:

1. `crawler` скачивает страницу и выполняет upsert в `documents`.
2. `crawler` сохраняет позицию обхода в `crawl_state` и задачи Wikipedia в
   `crawl_queue`.
3. `linguistics` читает `documents` и записывает `processed_documents`,
   `document_terms` и глобальные частоты.
4. Я вручную запускаю программы, проверяю коллекции и объясняю получившуюся схему.

Именно это и нужно показать преподавателю: не ручной ввод данных, а понимание
того, какая программа создаёт каждую коллекцию и для чего она используется.

## 2. Какие коллекции нужно знать

| Коллекция | Что в ней хранится | Кто создаёт |
|---|---|---|
| `documents` | URL, источник, сырой HTML, хеш и время загрузки | crawler |
| `crawl_queue` | очередь категорий и страниц Wikipedia | crawler |
| `crawl_state` | позиция продолжения arXiv и Microsoft Learn | crawler |
| `processed_documents` | основной текст без HTML и метрики документа | linguistics |
| `document_terms` | токены, леммы и частоты внутри документа | linguistics |
| `token_frequencies` | частота каждого токена во всём корпусе | linguistics |
| `lemma_frequencies` | частота каждой леммы во всём корпусе | linguistics |
| `linguistics_state` | версия парсера, блокировка и согласованность частот | linguistics |

На защите достаточно подробно показать пять сущностей:

1. `documents` — что было скачано.
2. Индексы `documents` — почему нет дублей.
3. `crawl_state` и `crawl_queue` — как обход продолжается после остановки.
4. `processed_documents` — какой текст получен из HTML.
5. `document_terms` — какие токены и леммы используются индексатором.

## 3. Подготовка за день до защиты

### Шаг 1. Перейти в проект

В терминале WSL:

```bash
cd /home/ubuntuwsl/mai/mai-ir
```

Все следующие команды Linux выполняются из этого каталога.

### Шаг 2. Запустить MongoDB

```bash
docker compose up -d
docker compose ps
```

Ожидаемый смысл вывода:

```text
NAME             STATUS   PORTS
mai-ir-mongodb   Up       127.0.0.1:27017->27017/tcp
```

Точное оформление таблицы может отличаться. Важно увидеть:

- контейнер `mai-ir-mongodb`;
- состояние `Up`;
- порт `127.0.0.1:27017`.

### Шаг 3. Проверить соединение

```bash
docker compose exec mongodb mongosh --quiet --eval \
  'db.adminCommand({ping: 1})'
```

Ожидаемый результат содержит:

```text
ok: 1
```

Если `ok: 1` получен, сервер MongoDB работает независимо от наличия Compass.

### Шаг 4. Быстро проверить наличие корпуса

```bash
docker compose exec mongodb mongosh --quiet mai_ir --eval '
print("Сырых документов:", db.documents.countDocuments({}, {hint: "_id_"}));
print("Принято документов:", db.processed_documents.countDocuments(
  {accepted: true},
  {hint: "accepted_1_source_1"}
));
'
```

На момент подготовки инструкции ожидаются приблизительно такие значения:

```text
Сырых документов: 170393
Принято документов: 151182
```

Корпус продолжает пополняться, поэтому более новые значения являются нормой.
Использованные `hint` заставляют MongoDB считать записи по уже существующим
индексам, поэтому команда выполняется быстро.

### Шаг 5. Проверить Compass заранее

Если MongoDB Compass ещё не установлен, скачать его с официальной страницы:

https://www.mongodb.com/products/tools/compass

Compass лучше проверить заранее, а не устанавливать перед преподавателем.

## 4. Не перепутать, куда вводить команды

В инструкции используются три разных места ввода.

### Терминал WSL

Приглашение выглядит примерно так:

```text
ubuntuwsl@LAPTOP:~/mai/mai-ir$
```

Сюда вводятся команды `docker`, `uv`, `cmake` и пути к программам:

```bash
docker compose ps
./.build/linguistics config.yaml
```

### Консоль mongosh

После входа приглашение выглядит примерно так:

```text
mai_ir>
```

Сюда вводятся JavaScript-подобные запросы MongoDB:

```javascript
db.documents.countDocuments()
```

Команду `docker compose ...` нельзя вводить внутри `mongosh`, а запрос
`db.documents...` нельзя вводить непосредственно в Bash.

### MongoDB Compass

В Compass запросы вводятся в поля **Filter**, **Project** и на вкладке
**Aggregations**. Команды `docker compose` в Compass не вводятся.

## 5. Вариант A — подробный показ через MongoDB Compass

### 5.1. Подключение Compass к проекту

1. В WSL выполнить:

   ```bash
   docker compose up -d
   docker compose ps
   ```

2. Открыть MongoDB Compass в Windows.
3. Нажать **Add New Connection**.
4. В поле URI вставить:

   ```text
   mongodb://127.0.0.1:27017/mai_ir
   ```

5. При желании задать имя подключения `MAI IR local`.
6. Аутентификацию оставить выключенной: локальный контейнер не требует логина и
   пароля.
7. Нажать **Connect** или **Save & Connect**.

После подключения слева должен появиться сервер, а внутри него база `mai_ir`.
Если сразу открылась другая вкладка, нажать на базу `mai_ir` в левой панели.

Что сказать преподавателю:

> MongoDB запущена локально в Docker. Порт 27017 опубликован только на localhost.
> Все программы получают тот же URI из секции `db` файла `config.yaml`.

### 5.2. Показать список коллекций

1. В левой панели раскрыть базу `mai_ir`.
2. Показать названия коллекций.
3. Объяснить разделение:
   - `documents`, `crawl_state`, `crawl_queue` относятся к crawler;
   - остальные коллекции создаёт C++-модуль linguistics.

Что сказать:

> Я разделил сырой документ, состояние обхода и результаты лингвистической
> обработки. Поэтому можно изменить парсер и переобработать HTML, не скачивая
> страницы повторно.

### 5.3. Показать сырые документы

1. Нажать коллекцию `documents`.
2. Открыть вкладку **Documents**.
3. В поле **Filter** вставить:

   ```javascript
   { source: "wikipedia" }
   ```

4. В поле **Project** вставить:

   ```javascript
   {
     source: 1,
     source_id: 1,
     title: 1,
     url: 1,
     raw_size: 1,
     fetched_at: 1,
     checked_at: 1,
     content_hash: 1
   }
   ```

5. Нажать **Find** или **Apply** — название зависит от версии Compass.

Проекция специально не включает `raw_html`: иначе Compass попытается показать
весь HTML и документ будет неудобно читать.

Что показать в одной записи:

| Поле | Что означает |
|---|---|
| `source` | источник документа |
| `source_id` | идентификатор внутри источника |
| `title` | заголовок страницы |
| `url` | нормализованный URL |
| `raw_size` | размер сырого HTML в байтах |
| `fetched_at` | когда содержимое было загружено |
| `checked_at` | когда страница проверялась последний раз |
| `content_hash` | SHA-256 сырого HTML для обнаружения изменений |

Последовательно заменить фильтр и показать остальные источники:

```javascript
{ source: "arxiv" }
```

```javascript
{ source: "microsoft_learn" }
```

Что сказать:

> Схема едина для всех источников. Поля `source` и `source_id` позволяют однозначно
> определить документ, а `content_hash` используется для проверки изменений.

### 5.4. Показать точное количество по источникам

1. Оставаясь в `documents`, открыть вкладку **Aggregations**.
2. Добавить первую стадию `$group` со следующим содержимым:

   ```javascript
   {
     _id: "$source",
     documents: { $sum: 1 }
   }
   ```

3. Добавить вторую стадию `$sort`:

   ```javascript
   { _id: 1 }
   ```

4. Нажать **Run**.

В некоторых версиях Compass есть текстовый режим pipeline. В нём можно вставить
сразу весь массив:

```javascript
[
  {
    $group: {
      _id: "$source",
      documents: { $sum: 1 }
    }
  },
  {
    $sort: { _id: 1 }
  }
]
```

Ожидаемый результат для текущего корпуса:

| Источник | Документов |
|---|---:|
| `arxiv` | 11 038 |
| `microsoft_learn` | 80 899 |
| `wikipedia` | 78 456 |

Значения могут увеличиться после нового запуска crawler.

Что сказать:

> Это точная группировка документов, которые сейчас физически находятся в
> MongoDB. Она не берёт числа из отчёта или конфигурации.

### 5.5. Показать защиту от дублей

1. Открыть коллекцию `documents`.
2. Перейти на вкладку **Indexes**.
3. Найти:
   - `source_1_source_id_1`;
   - `source_1_url_1`.
4. У обоих показать признак `unique`.

Что сказать:

> Первый уникальный индекс запрещает повтор одного идентификатора внутри
> источника. Второй запрещает повтор нормализованного URL. Crawler выполняет
> upsert, поэтому повторный обход обновляет запись, а не создаёт копию.

Индекс `source_1_checked_at_1` используется для выбора документов, которые давно
не проверялись и должны быть обойдены повторно.

### 5.6. Показать продолжение crawler после остановки

1. Открыть `crawl_state` → **Documents**.
2. Показать документы с `_id` вроде `arxiv:cs.IR` и
   `microsoft_learn:main`.
3. Открыть `crawl_queue`.
4. В поле **Filter** можно вставить:

   ```javascript
   { source: "wikipedia" }
   ```

5. Показать поля `status`, `kind`, `title`, `depth`, `attempts` и timestamps.

Что сказать:

> У arXiv сохраняются категория, месяц и позиция Atom-выдачи. У Microsoft Learn
> сохраняются sitemap и индекс URL. Wikipedia использует постоянную очередь со
> статусами задач. Поэтому после Ctrl+C обход продолжается с сохранённого места.

### 5.7. Показать результат выделения текста

1. Открыть `processed_documents` → **Documents**.
2. В **Filter** вставить:

   ```javascript
   { accepted: true }
   ```

3. В **Project** вставить:

   ```javascript
   {
     source: 1,
     source_id: 1,
     title: 1,
     text_size: 1,
     word_count: 1,
     token_count: 1,
     parser_version: 1,
     accepted: 1
   }
   ```

4. Нажать **Find** или **Apply**.

Что сказать:

> Это уже результат C++-обработчика. Сырой HTML остался в `documents`, а здесь
> лежит основной текст после отдельных XPath-правил Wikipedia, arXiv и Microsoft
> Learn. `accepted: true` означает, что документ прошёл порог 200 токенов.

Если преподаватель попросит увидеть сам текст, убрать проекцию или добавить поле
`text`, открыть один документ и показать только начало. Не нужно разворачивать
несколько больших текстов одновременно.

### 5.8. Показать токены и леммы

1. Открыть `document_terms` → **Documents**.
2. Открыть одну запись.
3. Развернуть начало массивов `tokens` и `lemmas`.

Элемент массива выглядит так:

```text
["database", 7]
```

Это означает, что терм `database` встретился в данном документе семь раз.

Затем открыть `lemma_frequencies` и в **Filter** ввести:

```javascript
{ _id: "database" }
```

Что сказать:

> `document_terms` содержит частоты внутри конкретного документа и является
> входом для построения булева индекса. `lemma_frequencies` содержит частоту во
> всём корпусе и используется для статистики и закона Ципфа.

### 5.9. Чем закончить показ Compass

Открыть терминал и выполнить:

```bash
ls -lh results/boolean_index
```

Что сказать:

> MongoDB заканчивается на подготовленных документах и термах. Сам инвертированный
> индекс создан моей C++-программой в собственном бинарном формате и находится в
> этих четырёх файлах.

## 6. Вариант B — полный показ без Compass через mongosh

Этот вариант показывает те же факты только командами. Его стоит использовать,
если Compass не установлен, не подключается или преподаватель просит выполнить
точный запрос.

### 6.1. Войти в базу

В терминале WSL:

```bash
docker compose exec mongodb mongosh mai_ir
```

После подключения появится приглашение:

```text
mai_ir>
```

Все команды следующих подразделов вводятся после этого приглашения.

### 6.2. Показать коллекции

Внутри `mongosh`:

```javascript
show collections
```

Ожидаются коллекции:

```text
crawl_queue
crawl_state
document_terms
documents
lemma_frequencies
linguistics_state
processed_documents
token_frequencies
```

Порядок строк не важен.

### 6.3. Показать количество документов

Быстрый точный общий подсчёт по индексу `_id`:

```javascript
db.documents.countDocuments({}, { hint: "_id_" })
```

Точная группировка по источникам:

```javascript
db.documents.aggregate(
  [
    {
      $group: {
        _id: "$source",
        documents: { $sum: 1 }
      }
    },
    {
      $sort: { _id: 1 }
    }
  ],
  {
    hint: { source: 1, source_id: 1 }
  }
)
```

Ожидаются три группы: `arxiv`, `microsoft_learn` и `wikipedia`.

### 6.4. Показать один сырой документ

```javascript
db.documents.findOne(
  { source: "wikipedia" },
  {
    _id: 0,
    source: 1,
    source_id: 1,
    title: 1,
    url: 1,
    raw_size: 1,
    fetched_at: 1,
    checked_at: 1,
    content_hash: 1
  }
)
```

Подтвердить наличие HTML, не печатая его полностью:

```javascript
rawDocument = db.documents.findOne({ source: "wikipedia" })
rawDocument.raw_html.slice(0, 500)
```

Преобразовать Unix timestamp в читаемую дату:

```javascript
new Date(rawDocument.fetched_at * 1000)
```

### 6.5. Показать MongoDB-индексы

```javascript
db.documents.getIndexes()
```

В выводе найти:

```text
name: 'source_1_source_id_1', unique: true
name: 'source_1_url_1',       unique: true
```

### 6.6. Показать состояние обхода

```javascript
printjson(db.crawl_state.find({}).limit(10).toArray())
```

```javascript
printjson(db.crawl_queue.findOne({ source: "wikipedia" }, { _id: 0 }))
```

Первый запрос показывает позицию источника, второй — одну задачу очереди
Wikipedia.

### 6.7. Показать обработанный документ

```javascript
db.processed_documents.findOne(
  { accepted: true },
  {
    _id: 0,
    source: 1,
    source_id: 1,
    title: 1,
    text_size: 1,
    word_count: 1,
    token_count: 1,
    parser_version: 1,
    accepted: 1
  }
)
```

Показать первые 500 символов основного текста:

```javascript
processedDocument = db.processed_documents.findOne({ accepted: true })
processedDocument.text.slice(0, 500)
```

### 6.8. Показать токены и леммы

```javascript
db.document_terms.findOne(
  {},
  {
    _id: 0,
    source_id: 1,
    tokens: { $slice: 10 },
    lemmas: { $slice: 10 }
  }
)
```

Показать глобальную частоту конкретной леммы:

```javascript
db.lemma_frequencies.findOne({ _id: "database" })
```

Показать состояние лингвистического обработчика:

```javascript
db.linguistics_state.findOne({ _id: "frequencies" })
```

Поле `dirty: false` означает, что глобальные частоты находятся в согласованном
состоянии. `parser_version` показывает версию правил обработки.

### 6.9. Выйти из mongosh

```javascript
exit
```

После `exit` снова появится обычное приглашение Bash.

## 7. Готовый сценарий ответа преподавателю

Ниже короткий текст, который можно проговорить во время демонстрации.

### Вступление

> MongoDB у меня запущена локально в Docker. Crawler сохраняет в неё сырой HTML,
> метаданные и состояние обхода. C++-обработчик читает сырой HTML и записывает
> извлечённый текст, токены, леммы и частоты. Булев индекс затем строится по этим
> данным и хранится уже в собственных бинарных файлах.

### При показе documents

> Это сырые документы. У каждого есть источник, идентификатор, нормализованный
> URL, исходный HTML, SHA-256 и Unix timestamps. HTML сохраняется, чтобы правила
> выделения текста можно было менять без повторной загрузки сайта.

### При показе Indexes

> Уникальные индексы по `source + source_id` и `source + url` не дают сохранить
> дубль. Повторный обход выполняет upsert и обновляет существующую запись.

### При показе crawl_state

> Здесь хранится позиция обхода. Поэтому после Ctrl+C программа продолжает работу
> с сохранённого места, а не начинает весь источник сначала.

### При показе processed_documents

> Здесь уже основной текст, выделенный отдельными правилами для Wikipedia, arXiv
> и Microsoft Learn. Документ принимается в корпус, если содержит не менее 200
> токенов.

### При показе document_terms

> Здесь хранятся пары «терм — частота» для одного документа. Леммы из этой
> коллекции потоково читает C++-построитель инвертированного индекса.

## 8. Минимальный порядок показа за пять минут

Если времени мало, достаточно следующей последовательности:

1. В WSL выполнить `docker compose ps`.
2. В Compass открыть `mai_ir` и показать список коллекций.
3. Открыть `documents` с проекцией без `raw_html`.
4. На вкладке **Indexes** показать два `unique` индекса.
5. Открыть `crawl_state` и объяснить продолжение после остановки.
6. Открыть один `processed_documents` с `accepted: true`.
7. Открыть один `document_terms` и развернуть `tokens` и `lemmas`.
8. В терминале показать `ls -lh results/boolean_index`.

Такой показ подтверждает всю цепочку: загрузка → хранение → продолжение обхода →
выделение текста → лингвистика → данные для индекса.

## 9. Если Compass не подключается

### Проверка 1. Работает ли контейнер

В WSL:

```bash
docker compose ps
```

Если контейнера нет или статус не `Up`:

```bash
docker compose up -d
```

### Проверка 2. Отвечает ли MongoDB

```bash
docker compose exec mongodb mongosh --quiet --eval \
  'db.runCommand({ping: 1})'
```

Если получен `ok: 1`, база исправна, а проблема относится только к Compass.

### Проверка 3. Опубликован ли порт

```bash
ss -ltnp | grep 27017
```

Должен присутствовать адрес `127.0.0.1:27017`.

### Проверка 4. Правильная ли строка Compass

Использовать ровно:

```text
mongodb://127.0.0.1:27017/mai_ir
```

Не нужно включать TLS, SSH tunnel, имя пользователя или пароль.

### Проверка 5. Видит ли Windows порт WSL

В PowerShell:

```powershell
Test-NetConnection 127.0.0.1 -Port 27017
```

Ожидается:

```text
TcpTestSucceeded : True
```

Если `mongosh` внутри WSL работает, а этот тест возвращает `False`, проблема в
пробросе localhost между Windows и WSL, а не в данных проекта. В таком случае на
защите можно без потери функциональности использовать вариант через `mongosh`.

## 10. Чего не делать на защите

- Не выполнять `db.dropDatabase()`.
- Не выполнять `drop`, `deleteOne`, `deleteMany` или `remove`.
- Не запускать `docker compose down -v`: параметр `-v` удалит volume с корпусом.
- Не редактировать документы через Compass.
- Не выводить целиком большой `raw_html` или `text`.
- Не запускать полный crawler или полную переобработку корпуса без необходимости.
- Не говорить, что булев индекс хранится в MongoDB: он находится в
  `results/boolean_index/`.
