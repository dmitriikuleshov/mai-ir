# Лабораторная работа 4. Лемматизация

## 1. Цель

Лемматизация приводит разные словоформы к общей словарной форме:

```text
queries   -> query
retrieved -> retrieve
children  -> child
indices   -> index
```

Это уменьшает разрыв между формулировкой запроса и текстом документа. Булевый
индекс строится именно по леммам, поэтому запрос `queries` ищет posting list
леммы `query`.

Лемматизатор является частью `src/linguistics/core.cpp` и вызывается сразу после
токенизации. Поисковая утилита использует тот же код для нормализации терминов
запроса, поэтому обработка корпуса и запроса согласована.

## 2. Алгоритм

Для каждого токена применяется следующая последовательность:

1. Если токен содержит не только ASCII-буквы, он сохраняется без морфологических
   изменений. Это защищает `c++`, `.net`, числа и составные технические термины.
2. Проверяются встроенные нерегулярные формы.
3. Выполняется бинарный поиск в словаре исключений WordNet.
4. Если исключение не найдено, применяются правила английских суффиксов.

Поддерживаются правила:

- `-ies` → `y`;
- `-ing` с обработкой удвоенной согласной и восстановлением `e`;
- `-ed` с обработкой удвоенной согласной и восстановлением `e`;
- множественные `-sses`, `-shes`, `-ches`, `-xes`, `-zes`, `-oes`;
- обычное окончание `-s` с исключениями `ss`, `us`, `is`.

Словарь `resources/wordnet_exceptions.tsv` содержит 5 940 исключений Princeton
WordNet. Его лицензия лежит рядом в `resources/WORDNET_LICENSE.txt`.

Порядок проверок в коде принципиален:

```cpp
static char *lemmatize(const char *word,
                       const LemmaDictionary *dictionary) {
    if (!ascii_word(word)) {
        return duplicate_range(word, std::strlen(word));
    }

    for (const LemmaPair &pair : IRREGULAR_LEMMAS) {
        if (std::strcmp(word, pair.form) == 0) {
            return duplicate_range(pair.lemma, std::strlen(pair.lemma));
        }
    }

    const char *dictionary_lemma = dictionary_find(dictionary, word);
    if (dictionary_lemma != nullptr) {
        return duplicate_range(dictionary_lemma,
                               std::strlen(dictionary_lemma));
    }

    // Только после исключений применяются общие suffix rules.
    // ... -ies, -ing, -ed, plural -es, final -s ...
}
```

Если применить suffix rule раньше словаря, `children`, `better` и другие
нерегулярные формы будут нормализованы неверно.

## 3. Почему недостаточно только стемминга

Стеммер механически отрезает окончания и может вернуть основу, не являющуюся
словом. Здесь требуется лемматизация: `better` должно стать `good`, `children` —
`child`, `analyses` — `analysis`. Поэтому правила дополнены словарём исключений и
нерегулярными формами.

При этом реализация не является полноценным контекстным морфологическим
анализатором: часть неоднозначности без контекста принципиально неразрешима.
Например, `axes` может быть множественным числом и от `axis`, и от `axe`.

## 4. Структуры данных

Словарь загружается в собственный массив пар `(form, lemma)`, сортируется через
`qsort`, затем ищется бинарным поиском. `std::map` и `unordered_map` не
используются.

После нормализации всех токенов леммы сортируются и объединяются в
`FrequencyArray`:

```javascript
lemmas: [
  ["database", 9],
  ["index", 16],
  ["query", 11]
]
```

Частоты токенов и лемм сохраняются отдельно. Это позволяет сравнивать словари и
при необходимости строить индекс по исходным формам.

## 5. Глобальные частоты и обновления

Коллекции:

- `token_frequencies`: `{_id: token, count: total}`;
- `lemma_frequencies`: `{_id: lemma, count: total}`.

При изменении документа программа не пересчитывает весь корпус:

1. читает старые `tokens` и `lemmas` из `document_terms`;
2. добавляет их в delta со знаком `-1`;
3. добавляет новые частоты со знаком `+1`;
4. сортирует и суммирует delta;
5. выполняет `$inc` глобальных счётчиков.

Нулевые и отрицательные частоты после пакета удаляются.

## 6. Согласованность и восстановление

MongoDB bulk-операции разных коллекций не образуют одну транзакцию. Поэтому
используется собственный протокол восстановления:

1. Перед обработкой в `linguistics_state` устанавливается `dirty: true`.
2. Глобальные частоты обновляются delta.
3. Сначала записывается `document_terms` — восстановимый источник истины.
4. Затем записывается `processed_documents` — commit marker документа.
5. После штатного завершения устанавливается `dirty: false`.

Если процесс аварийно завершился и остался `dirty: true`, следующий запуск
полностью перестраивает `token_frequencies` и `lemma_frequencies` агрегацией из
`document_terms`.

Порядок commit виден непосредственно в конце пакетной записи:

```cpp
// document_terms можно использовать для полного восстановления частот.
execute_bulk(terms_bulk, "запись термов документов");

// processed_documents записывается последним и служит commit marker.
execute_bulk(processed_bulk, "запись обработанных документов");
```

Если сбой произойдёт между этими строками, `processed_documents` ещё не подтвердит
завершение. Следующий запуск повторит документ, а dirty-протокол восстановит
глобальные счётчики.

Отдельная lease-блокировка `processor_lock` не позволяет двум экземплярам
лингвистического обработчика одновременно менять частоты. Lease продлевается
после каждого пакета и освобождается после завершения.

## 7. Идемпотентность

Документ считается актуальным, если совпадают:

- `content_hash` сырого HTML;
- `parser_version`.

При совпадении документ пропускается. Если crawler обновил HTML или разработчик
увеличил версию алгоритма, документ обрабатывается заново с корректной delta
старых и новых частот.

## 8. Запуск и проверка

Лемматизация запускается общей программой:

```bash
./.build/linguistics config.yaml
```

Только морфологический тест:

```bash
./.build/linguistics_tests morphology
```

Первые леммы документа:

```bash
docker exec mai-ir-mongodb mongosh --quiet --eval '
const d = db.getSiblingDB("mai_ir");
printjson(d.document_terms.findOne({}, {lemmas: {$slice: 20}}));'
```

Самые частые леммы:

```bash
docker exec mai-ir-mongodb mongosh --quiet --eval '
const d = db.getSiblingDB("mai_ir");
printjson(d.lemma_frequencies.find().sort({count: -1}).limit(20).toArray());'
```

## 9. Текущие результаты

- словарь токенов: 3 634 478;
- словарь лемм: 3 565 769;
- всего токенов: 396 830 385;
- средняя длина токена: 5,77 символа.

Уменьшение словаря показывает, что разные формы объединились, но эффект умеренный:
корпус содержит много имён, кода, идентификаторов и составных технических токенов,
которые намеренно не изменяются.

В `statistics.json` есть синтетическая проверка морфологии:

| Метрика | Значение |
|---|---:|
| Точность словарных примеров | 1,0 |
| Macro recall без лемматизации | 0,375 |
| Macro recall после лемматизации | 1,0 |
| Macro precision на однозначных группах | 1,0 |
| Precision неоднозначного `axes` | 0,5 |

Это диагностика морфологии, а не оценка ранжированной поисковой выдачи. P, DCG,
NDCG и ERR требуют набора запросов и экспертных оценок релевантности.

## 10. Тестирование

Тест `morphology` проверяет:

- `queries` → `query`;
- `retrieved` → `retrieve`;
- WordNet exception `abaci` → `abacus`;
- irregular form `children` → `child`.

Тест `recovery` дополнительно проверяет порядок записи: `document_terms` должен
записываться раньше commit marker в `processed_documents`.

## 11. Что показать преподавателю

1. Разницу между токеном, стемом и леммой.
2. Порядок: irregular → WordNet → suffix rules.
3. Несколько форм `queries/query`, `retrieved/retrieve`, `children/child`.
4. Отдельные массивы `tokens` и `lemmas` одного документа.
5. Глобальные коллекции частот.
6. Delta-обновление изменившегося документа.
7. `dirty`-флаг, порядок commit и восстановление после сбоя.
8. Ограничение неоднозначных форм без контекста.

## 12. Ограничения

- Морфология рассчитана на английский язык.
- Нет определения части речи по контексту.
- Не-ASCII и технические токены сохраняются как есть.
- Словарь исключений покрывает WordNet, но не все новые термины и имена.
- Синтетические метрики нельзя выдавать за качество поисковой выдачи.

## 13. Пошаговые примеры правил

### `queries -> query`

```text
queries
length > 4 and suffix "ies"
remove ies, append y
query
```

### `running -> run`

```text
running
remove ing -> runn
last two characters equal and consonant -> remove one n
run
```

### `making -> make`

```text
making
remove ing -> mak
stem ends with mak -> restore e
make
```

### `children -> child`

Это не suffix rule. Форма находится среди irregular/WordNet раньше общих правил.

### `caches`

Общие правила могут быть недостаточны для некоторых доменных слов. Именно поэтому
сначала проверяется словарь исключений. Если нужной формы нет и результат неверен,
словарь можно расширить, увеличить `parser_version` и пересчитать корпус.

## 14. Как загружается словарь

Файл TSV содержит строки вида:

```text
abaci<TAB>abacus
analyses<TAB>analysis
indices<TAB>index
```

Загрузчик:

1. читает файл строка за строкой;
2. делит по tab;
3. создаёт собственный массив `LemmaPair`;
4. сортирует по `form` через `qsort`;
5. выполняет `dictionary_find` бинарным поиском.

Если одна форма имеет несколько возможных лемм, статический словарь без контекста
должен выбрать одну. Это источник неоднозначности, а не ошибка binary search.

## 15. Числовой пример delta-обновления

Старая версия документа:

```javascript
lemmas: [
  ["database", 3],
  ["index", 2],
  ["query", 1]
]
```

Новая версия:

```javascript
lemmas: [
  ["database", 2],
  ["index", 5],
  ["search", 1]
]
```

Создаваемые delta до группировки:

```text
database -3
index    -2
query    -1
database +2
index    +5
search   +1
```

После сортировки и суммирования:

```text
database -1
index    +3
query    -1
search   +1
```

Именно эти четыре `$inc` применяются к глобальной коллекции. Полный словарь не
пересчитывается при каждом обычном изменении.

## 16. Сценарии сбоя

### Сбой до записи глобальных delta

Commit marker не обновлён. Документ будет обработан снова. Старые document terms
ещё соответствуют старым global counts.

### Сбой после global delta, но до document_terms

`dirty=true`. При следующем запуске global collections будут перестроены из старых
document_terms, затем документ обработается заново.

### Сбой после document_terms, но до processed_documents

`dirty=true`, document_terms уже новая. Rebuild сделает globals по новой версии.
Commit marker старый, поэтому документ снова обработается. Delta сначала вычтет
текущую document_terms и прибавит тот же новый результат: итог останется верным.

### Сбой после processed_documents, но до `dirty=false`

Все документы согласованы, но следующий запуск выполнит лишний полный rebuild.
Это безопасно: цена — время, не неверные данные.

## 17. Lease-блокировка подробно

`processor_lock` хранит owner и `lock_until`:

```javascript
{
  _id: "processor_lock",
  lock_owner: "24-char-generated-id",
  lock_until: 1790000600
}
```

Acquire разрешён, если lock истёк, отсутствует или принадлежит тому же owner.
После каждого batch lease продлевается. При штатном завершении owner удаляется и
`lock_until=0`.

Почему lease, а не вечный mutex: если процесс погибнет, вечная блокировка потребует
ручного вмешательства. Lease освобождается временем.

## 18. Локальные и глобальные частоты

Пусть три документа содержат:

```text
D0: database=2, query=1
D1: database=1, index=4
D2: query=3
```

`document_terms` хранит три отдельных массива. `lemma_frequencies` должна хранить:

```text
database=3
index=4
query=4
```

Инвариант можно проверить aggregation:

```javascript
db.document_terms.aggregate([
  {$unwind: "$lemmas"},
  {$group: {
    _id: {$arrayElemAt: ["$lemmas", 0]},
    count: {$sum: {$arrayElemAt: ["$lemmas", 1]}}
  }}
])
```

Именно такую идею использует rebuild.

## 19. Производительность

Пусть документ имеет `W` токенов, словарь исключений `D` записей.

- lemmatization одного обычного слова: `O(log D)` плюс небольшое число suffix checks;
- всех слов: `O(W log D)`;
- сортировка лемм для frequency array: `O(W log W)`;
- delta sorting batch: `O(U log U)`, где `U` — суммарное число уникальных terms
  документов пакета.

Dictionary загружается один раз на процесс, а не для каждого документа.

## 20. Как проверить конкретную форму

Тестовая программа принимает только готовый testcase, поэтому для защиты удобно
показать существующий morphology test в `tests/linguistics/test_core.cpp`:

```cpp
const char *morphology_text =
    "queries query queries retrieved abaci children";

expect(frequency(&morphology.lemmas, "query") == 3,
       "лемматизация queries");
expect(frequency(&morphology.lemmas, "retrieve") == 1,
       "лемматизация retrieved");
```

Это проверяет не только строковый результат, но и объединение частот нескольких
словоформ.

## 21. Контрольные вопросы

### Чем lemma отличается от stem?

Lemma должна быть словарным словом (`better -> good`). Stem может быть технической
основой после механического отсечения и не обязан существовать как слово.

### Зачем сохранять и tokens, и lemmas?

Tokens нужны для анализа исходных форм и возможного точного поиска; lemmas — для
объединения морфологии. Разница словарей является измеримым результатом.

### Почему `axes` показывает precision 0.5?

Одна строка без контекста соответствует `axis` или `axe`. Rule-based analyzer без
POS/context выбирает одно значение и ошибается для второго смысла.

### Можно ли применить русский словарь?

Текущие rules и WordNet английские. Для русского нужен другой morphology module,
но interfaces FrequencyArray и downstream index можно сохранить.

### Почему global counts вообще нужны, если index использует document_terms?

Для Zipf, top terms, corpus statistics и будущего IDF. Индексатору они не нужны,
что уменьшает связанность компонентов.
