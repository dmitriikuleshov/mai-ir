# Лабораторная работа 5. Закон Ципфа–Мандельброта

## 1. Теория

Если термины отсортировать по убыванию частоты, классический закон Ципфа имеет вид:

```text
f(r) = C / r
```

где `r` — ранг термина, `f(r)` — его частота, `C` — масштаб.

Более гибкая модель Мандельброта:

```text
f(r) = C / (r + b)^s
```

Параметр `b` корректирует наиболее частые термины, `s` задаёт наклон. В
логарифмических координатах зависимость близка к прямой:

```text
log f(r) = log C - s * log(r + b)
```

## 2. Какие данные используются

График строится по глобальным частотам лемм из `lemma_frequencies`, а не по одному
документу. Значения сортируются по `count` по убыванию.

Параметры `config.yaml`:

- `zipf_max_terms: 100000` — максимум рангов на графике;
- `zipf_fit_terms: 10000` — сколько первых рангов участвует в подборе модели;
- `top_terms: 30` — сколько самых частых токенов и лемм записать в JSON.

Ограничение 100 тысяч уменьшает объём построения SVG, но частоты рассчитаны по
всему корпусу.

## 3. Подбор параметров Мандельброта

Алгоритм перебирает 101 кандидат `b`:

- отдельно `b = 0`;
- ещё 100 значений в логарифмической сетке примерно от `10^-2` до `10^4`.

Для каждого `b` строится линейная регрессия между:

```text
x = log(r + b)
y = log(f(r))
```

Из intercept получается `C = exp(intercept)`, из отрицательного slope — `s`.
Выбирается вариант с минимальной RMSE в логарифмическом пространстве.

Ключевой фрагмент подбора:

```cpp
for (size_t candidate = 0; candidate <= 100; ++candidate) {
    const double b = candidate == 0
        ? 0.0
        : std::pow(10.0, -2.0 + 6.0 * (candidate - 1) / 99.0);

    for (size_t index = 0; index < size; ++index) {
        const double x = std::log(static_cast<double>(index + 1) + b);
        const double y = std::log(static_cast<double>(frequencies[index]));
        sum_x += x;
        sum_y += y;
        sum_xx += x * x;
        sum_xy += x * y;
    }

    const double slope =
        (count * sum_xy - sum_x * sum_y) /
        (count * sum_xx - sum_x * sum_x);
    const double intercept = (sum_y - slope * sum_x) / count;

    // После расчёта RMSE сохраняется лучший кандидат.
    if (rmse < best.rmse) {
        best = {std::exp(intercept), b, -slope, rmse};
    }
}
```

В этой записи `index + 1` является рангом, потому что математический ранг начинается
с единицы, а индекс массива — с нуля.

## 4. Выходные файлы

Общая программа лингвистики создаёт:

- `results/statistics.json` — числа и параметры аппроксимации;

## 7. Текущий результат

Для 151 182 принятых документов:

```text
C = 1 040 308 162,39
b = 75,6463
s = 1,44465
RMSE(log) = 0,07857
```

Низкая RMSE в логарифмической шкале означает, что модель хорошо описывает общую
форму первых рангов. Значения `b > 0` и `s > 1` показывают, что реальный корпус
отличается от идеальной зависимости `1/r`, особенно для самых частых терминов.

Самые частые токены включают `the`, `of`, `to`, `and`, `a`, `in`. Это ожидаемые
английские служебные слова, потому что стоп-слова не удалялись. В корпусе также
очень часты `lt`, `gt`, `string`, `false`, `property`, что отражает большой объём
технической документации и следы линейного представления разметки/кода.

После лемматизации форма `is` объединяется с `be`, поэтому `be` поднимается среди
наиболее частых лемм. Это наглядный пример влияния лемматизации на частотный
словарь.

## 8. Как интерпретировать график

1. Обе оси логарифмические, поэтому степенная зависимость выглядит почти прямой.
2. Голова распределения содержит небольшое число очень частых слов.
3. Длинный хвост содержит миллионы редких терминов, имён и идентификаторов.
4. Красная линия Ципфа является грубой базовой моделью.
5. Зелёная линия Мандельброта лучше учитывает отклонение первых рангов.

Нельзя утверждать, что закон обязан выполняться идеально. Корпус смешивает научные
статьи, энциклопедию и документацию, а технические фрагменты создают дополнительные
частые токены.

## 10. Ограничения

- Аппроксимация использует первые 10 тысяч рангов, а не весь хвост.
- Поиск `b` выполняется по дискретной сетке, а не непрерывным оптимизатором.
- RMSE считается в логарифмической шкале и сильнее отражает относительную ошибку.
- Смешанная техническая тематика отличается от однородного корпуса естественного
  языка.
- Наличие `lt` и `gt` показывает, что извлечение текста ещё можно улучшать.

## 11. Ручной пример рангов

Пусть частоты шести лемм:

```text
term      count   rank
the        1000     1
be          520     2
database    340     3
index       250     4
query       205     5
search      170     6
```

Для идеального Ципфа с `C=1000` ожидалось бы:

```text
rank 1: 1000 / 1 = 1000
rank 2: 1000 / 2 = 500
rank 3: 1000 / 3 = 333.3
rank 6: 1000 / 6 = 166.7
```

Реальные 520, 340 и 170 близки, но не равны. На большом корпусе первые ранги часто
систематически отклоняются, поэтому добавляются `b` и свободный exponent `s`.

## 12. Почему логарифмическая шкала

Частота первого термина — десятки миллионов, а хвоста — единицы. На линейном
графике хвост сжался бы у нуля.

Логарифм превращает степенную зависимость в линейную:

```text
f(r) = C / (r+b)^s

log f(r) = log C - s log(r+b)
           └─────┘   └─┘
           intercept slope magnitude
```

После выбора `b` остаётся обычная линейная регрессия `y = intercept + slope*x`.

## 13. Формулы линейной регрессии

Для `n` точек:

```text
slope = (n Σxy - Σx Σy) / (n Σx² - (Σx)²)
intercept = (Σy - slope Σx) / n

C = exp(intercept)
s = -slope
```

Код накапливает `sum_x`, `sum_y`, `sum_xx`, `sum_xy`, поэтому не хранит отдельный
массив преобразованных точек.

RMSE:

```text
RMSE = sqrt(Σ(y_actual - y_predicted)² / n)
```

Ошибка измеряется в log space. Разница между частотой 10 и 20 важна примерно как
между 1000 и 2000 — это относительная, а не абсолютная ошибка.

## 14. Откуда берётся отсортированный ряд

В `lemma_frequencies` есть индекс `count: -1`. `frequency_values` делает query с:

```cpp
BSON_APPEND_INT64(&options, "limit", limit);
BSON_APPEND_INT32(&sort, "count", -1);
BSON_APPEND_INT32(&projection, "count", 1);
```

Текст термина для fit не нужен — только counts в ранговом порядке. Для top terms
отдельная функция читает и `_id`, и `count`.

## 15. Почему график рисуется не по всем 3,5 млн леммам

SVG с миллионами координат был бы огромным и плохо открывался. Берутся до 100
тысяч ranks, а для polyline — до 1600 равномерно распределённых по rank точек.

```cpp
const size_t points = size < 1600 ? size : 1600;
size_t rank = 1 + point * (size - 1) / (points - 1);
```

Это визуальная downsampling, а не изменение corpus counts.

## 16. Как читать текущие параметры

### `C ≈ 1.04e9`

Это scale модели, но не частота первого термина напрямую, потому что в denominator
есть `(1+b)^s`.

### `b ≈ 75.65`

Сдвиг заметный: первые десятки ranks требуют коррекции относительно чистого `r`.

### `s ≈ 1.445`

Наклон круче классического `s=1`. Частоты убывают быстрее идеального закона на
выбранном диапазоне.

### `RMSE(log) ≈ 0.0786`

Это средняя ошибка log frequency. Её нельзя читать как «7.86% точности» без
дополнительного преобразования.

## 17. Влияние обработки текста на Zipf

| Решение | Влияние |
|---|---|
| Не удалять stop words | выраженная голова the/of/to |
| Лемматизация | объединение is/are/was в be |
| Сохранять code tokens | высокие string/false/property |
| Не исправлять HTML artifacts | рост lt/gt |
| Порог 200 | исключение коротких страниц |
| Смешать три источника | смесь разных стилевых распределений |

График является характеристикой не только языка, но и всего pipeline.

## 18. Проверка воспроизводимости

1. Убедиться, что `dirty=false`.
2. Запустить linguistics без изменения parser version.
3. Большинство документов должно быть skipped.
4. Повторно созданный JSON должен иметь те же corpus totals, если crawler не
   добавил данные.
5. Параметры fit могут отличаться только при изменении counts или настроек.

## 19. Контрольные вопросы

### Закон Ципфа — это точный закон?

Нет, эмпирическая закономерность. Реальные корпуса отклоняются из-за жанра,
морфологии, preprocessing и конечного размера.

### Почему строим по леммам, а не tokens?

Леммы уменьшают искусственное разделение словоформ. Но можно строить оба графика;
текущая работа выбрала леммы как основу будущего поиска.

### Что показывает длинный хвост?

Большое число редких слов, имён, identifiers, опечаток и специализированных
терминов. Это аргумент в пользу сжатого словаря в будущей работе.

### Почему нельзя сравнивать RMSE разных настроек без оговорок?

Если меняются число fit terms, preprocessing или логарифмическая база, сравнение
неэквивалентно. Нужно фиксировать методику.

### Как улучшить fit?

Непрерывно оптимизировать b/s, исследовать разные rank ranges, добавить confidence
analysis и сравнить models. Для лабораторной grid + closed-form regression прозрачен
и воспроизводим.
