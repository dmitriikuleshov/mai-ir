# Лабораторные работы по информационному поиску

## Лабораторная работа №2. Поисковый робот

`crawler.py` асинхронно обходит три независимых источника: Wikipedia, arXiv HTML и
Microsoft Learn. Источники работают параллельно, но внутри каждого домена запросы идут
последовательно с собственной задержкой. Робот учитывает `robots.txt`, ответы `Retry-After`,
повторяет временно неудачные запросы с увеличивающейся паузой и не открывает более одного
соединения к одному хосту. Если `robots.txt` недоступен, соответствующий источник не
обкачивается до следующего запуска. HTML, превышающий безопасный для MongoDB предел,
отмечается в логе как `TOO_LARGE` и пропускается без остановки источника.

Документы, очередь Wikipedia и позиции обхода сохраняются в MongoDB. Поэтому объём корпуса
не ограничен оперативной памятью, а после остановки робот продолжает работу с сохранённой
позиции.

### Файлы

- `crawler.py` — робот и загрузчики трёх источников;
- `config.yaml` — подключение к MongoDB, задержки и параметры источников;
- `compose.yaml` — локальная MongoDB;
- `test_crawler.py` — автоматические проверки;
- `notebooks/` — анализ источников из первой лр.

### Установка

```bash
uv venv
uv pip install -r requirements.txt
```

### Запуск

Запустить MongoDB:

```bash
docker compose up -d
```

Если команда `docker` недоступна внутри WSL, в Docker Desktop нужно включить интеграцию
с используемой WSL-дистрибуцией.

Запустить робота. Путь к YAML является единственным аргументом:

```bash
uv run python crawler.py config.yaml
```

Контактный email владельца робота указан в `logic.user_agent` файла `config.yaml`.
Wikimedia отклоняет запросы роботов без контактной информации.

Остановка выполняется через `Ctrl+C`. Текущий URL или задача остаются в MongoDB, поэтому
следующий запуск продолжает обход. Перед завершением робот выводит количество документов
и статистику размеров по каждому источнику. Для короткой демонстрации можно задать
`max_documents: 10` у каждого источника. Для полного корпуса значение остаётся `null`.

### MongoDB

Коллекция `documents` содержит:

- `url` — нормализованный URL;
- `raw_html` — исходный HTML;
- `source` и `source_id`;
- `fetched_at` — Unix timestamp последней изменившей документ загрузки;
- `checked_at`, `content_hash`, `etag`, `last_modified` и метаданные источника.

Коллекции `crawl_state` и `crawl_queue` содержат позиции обхода и очередь Wikipedia.
Уникальные индексы не позволяют записывать один документ повторно.

При повторной проверке используются `ETag`, `Last-Modified`, дата обновления arXiv,
`lastmod` sitemap и SHA-256 HTML. Если документ не изменился, поле `raw_html` не
перезаписывается.

uv run pytest -q
