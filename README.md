# Лабораторные работы по информационному поиску

Проект собирает технический корпус из Wikipedia, arXiv HTML и Microsoft Learn,
хранит исходные документы в MongoDB и выполняет их лингвистическую обработку.

## Структура проекта

| Каталог | Что находится внутри |
|---|---|
| `src/` | исходный код робота и лингвистической обработки |
| `tests/` | автоматические тесты этих двух компонентов |
| `notebooks/` | три ноутбука и их локальные примеры документов |
| `resources/` | словарь WordNet и его лицензия |
| `results/` | итоговые статистика и график |

В корне находятся общая конфигурация, файлы сборки и `check.sh`, который собирает
C++-программу и запускает тесты.

Каталоги `.build/`, кеши и вспомогательные файлы результатов не добавляются в
Git. Итоговые `statistics.json` и `zipf.svg` сохраняются в репозитории.

## Установка

Для lesson-01 и lesson-02:

```bash
uv sync
docker compose up -d
```

Для лингвистического модуля нужны CMake, компилятор C++20, официальный C-драйвер MongoDB и
libxml2:

```bash
sudo apt update
sudo apt install build-essential cmake libmongoc-dev libbson-dev libxml2-dev
```

## Лабораторная работа №3 (lesson-04). Лингвистическая обработка

Lesson-04 полностью написан на C++. Python в сборке и выполнении этой лабораторной
работы не используется.

Программа самостоятельно:

1. Потоково читает сырой HTML из MongoDB.
2. Выделяет основной текст по отдельным правилам для трёх источников.
3. Токенизирует и лемматизирует текст.
4. Сохраняет обработанные документы и частоты в MongoDB.
5. Рассчитывает скорость, качество лемматизации и закон Ципфа–Мандельброта.
6. Записывает статистику в JSON и строит график SVG.

### Сборка и запуск

```bash
cmake -S . -B .build -DCMAKE_BUILD_TYPE=Release
cmake --build .build --parallel
./.build/linguistics config.yaml
```

Основные операции реализованы без STL-контейнеров. Для динамических массивов
используются собственные структуры, `malloc`/`realloc`, `qsort` и бинарный поиск.
`libmongoc` используется как драйвер MongoDB, а `libxml2` — как безопасный HTML- и
XPath-парсер. Логика лабораторной работы в эти библиотеки не вынесена.

### Правила обработки

Для Wikipedia, arXiv и Microsoft Learn заданы отдельные XPath-правила основного
содержимого и служебных блоков. Документы короче 500 токенов отмечаются как
`too_short` и не включаются в итоговый корпус.

Токенизатор приводит ASCII к нижнему регистру, унифицирует типографские дефисы и
апострофы и сохраняет формы `C++`, `C#`, `.NET`, `node.js`, `client-server`,
`sha-256`, `snake_case` и числа вида `3.14`. Стоп-слова не удаляются. Токены
длиннее 100 символов отбрасываются.

Лемматизатор сочетает правила английской морфологии, встроенные нерегулярные формы
и 5 940 исключений Princeton WordNet. Словарь находится в
`resources/wordnet_exceptions.tsv`, лицензия — в
`resources/WORDNET_LICENSE.txt`.

### MongoDB и обновления

- `processed_documents` — извлечённый текст и метрики документа;
- `document_terms` — частоты токенов и лемм документа;
- `token_frequencies` и `lemma_frequencies` — частоты по всему корпусу;
- `linguistics_state` — состояние согласованности частот.

Повторный запуск сравнивает `content_hash` и `parser_version`. Неизменившиеся
документы пропускаются, а глобальные частоты обновляются дельтами. Перед записью
устанавливается флаг `dirty`. Сначала записываются частоты документа, а запись в
`processed_documents` служит признаком полностью завершённой обработки. После
аварийной остановки следующий запуск пересобирает глобальные частоты из
`document_terms` и повторно обрабатывает незавершённые документы.

В MongoDB также устанавливается блокировка с ограниченным временем жизни. Она не
позволяет двум экземплярам обработчика одновременно изменять частоты. Во время
работы блокировка продлевается после каждого пакета документов, а после штатного
завершения освобождается.

При `Ctrl+C` программа заканчивает текущий пакет, сохраняет согласованное состояние,
освобождает блокировку и завершается. Следующий запуск продолжит обработку оставшихся
или изменившихся документов.

### Результаты текущего прогона

Из 25 123 сырых документов принято 13 078. Получено 36 795 118 токенов:

| Источник | Документов | Токенов |
|---|---:|---:|
| arXiv | 1 821 | 14 322 540 |
| Microsoft Learn | 3 587 | 4 955 724 |
| Wikipedia | 7 670 | 17 516 854 |

Средняя длина токена — 5,44 символа. Словарь содержит 834 253 токена и
808 595 лемм. Скорость токенизации — около 73 776 KiB/с. Полный миграционный
прогон версии 6 занял 124,3 с.

Архитектура обрабатывает корпус потоково и рассчитана на объём больше оперативной
памяти. Однако текущие 25 123 исходных документа ещё не дают формального масштаба
для оценки 5 по общим требованиям курса: для этого корпус нужно продолжить до
более чем 1 миллиона документов.

Результаты создаются здесь:

- `results/statistics.json` — численные показатели и оценка качества;
- `results/zipf.svg` — графики корпуса, Ципфа и Мандельброта.

Проверка словоформ в `statistics.json` является диагностикой самого
лемматизатора. Она не подменяет оценку ранжированной поисковой выдачи: P, DCG,
NDCG и ERR можно корректно посчитать после появления поиска и набора экспертных
оценок релевантности.

### Тесты лингвистического модуля

```bash
./check.sh
```

C++-тесты разделены на независимые тесткейсы и проверяют технические токены,
лемматизацию, исключения WordNet, Unicode-пробелы, выделение текста всех трёх
источников, конфигурацию, восстановление после сбоя и аппроксимацию Мандельброта.

## Лабораторная работа №2. Поисковый робот

`src/crawler/main.py` асинхронно обходит Wikipedia, arXiv HTML и Microsoft Learn.
Источники работают параллельно, а запросы к одному домену выполняются
последовательно с отдельной задержкой. Робот учитывает `robots.txt`, `Retry-After`,
ограничение размера ответа и повторяет временные ошибки с увеличивающейся паузой.
`Ctrl+C` немедленно прерывает в том числе ожидание повторного запроса. Временная
ошибка одного источника выводится одной строкой и не создаёт Python traceback.

```bash
uv run python src/crawler/main.py config.yaml
```

Сырые документы, очередь и позиции обхода сохраняются в MongoDB. Уникальные
индексы исключают повторную запись. Для обновлений используются `ETag`,
`Last-Modified`, даты arXiv и sitemap, а также SHA-256 HTML.

Пакетная проверка метаданных arXiv отправляется методом POST. Если API не может
обработать пакет, он автоматически делится пополам; единичный проблемный ID
откладывается и не останавливает остальные источники.

Новые записи arXiv запрашиваются отдельными месячными диапазонами. Позиция
хранится как месяц и смещение в MongoDB, поэтому crawler не упирается в ошибку
legacy API на глобальном `start=10000` и после остановки продолжает тот же месяц.

Тесты робота:

```bash
uv run pytest -q tests/crawler
```
